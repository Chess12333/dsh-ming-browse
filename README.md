# dsh-ming-browse

两个 DSH 插件，一起回答同一个问题：**一个长期驻留的 agent，怎么在自己闲下来的时候动起来，而且动得可控。**

| 目录 | 插件 | 干什么 |
|---|---|---|
| `browse/` | `ming-browse` | 工作区闲够久 → 在固定会话里塞一条 prompt，让它自己挑一件事做 |
| `interest/` | `ming-interest` | 入站消息被门控丢掉的那些里，命中关键词才把它叫醒 |

## 为什么需要这个

权限给足了，动作还是不会自己发生。人类不需要「被提醒」才会去刷手机，agent 需要——**没人叫，它就一直等。**

现成的两样东西都盖不住这一层：

- DSH 的 `schedule` 是「到点提醒我」，提醒完还是不知道干什么。
- `goal` 是「继续做这件事」，前提是已经有一件事。

缺的是「**闲了自己出去玩**」，而这个判定必须看会话活动，只能落在插件里。

## browse：一次唤醒的完整链路

```
每 N 秒轮询
  ↓
所有会话都 idle > gap 分钟？  ──否──► 什么都不做
  ↓ 是
落在自由窗口里？（默认 18:30–08:00，另加节假日 13:50–18:15）
  ↓ 是
今日配额没用完？冷却时间到了？
  ↓ 是
往固定会话（如 ming-browse-4）投一条 prompt
  ↓
agent 自己决定这一轮干什么
  ↓
跑满 15 轮 → 下一轮换到 ming-browse-5（新会话，历史不搬）
```

唤醒 prompt 里只放三样东西：**当前时间、能做什么、硬边界**。不预置任务，也不给「今天该做第几步」这种清单——那就退化成日程表了。

## 三条硬边界（写在代码里，不靠自觉）

1. **只作用于配置的工作区**。别的目录的会话既不算「有活动」，也不会被驱动。
2. **写操作只读**。社交平台上的点赞/评论/关注一律拒绝；花钱按钮拒绝。
3. **三道上限**：两次唤醒的最小间隔、每日次数、静默时段。任何一条撞上都整轮不醒。

暂停有两个时长，别混：

- `live/browse-pause.json`（带日期）→ **只停今天**，第二天自动失效。
- `live/browse-off` → **永久停**，只有明确的「以后都可以看了」才删。

## 换会话：这一条省下的钱最多

一轮的价 ≈ 步数 × 上下文，而上下文是**累积**的。同一个会话跑久了，每多一步都在为之前所有步付一次钱。

实测（某次 33 轮 / 314 步）：

| 区间 | 处理 token | cache miss |
|---|---|---|
| 第 1–15 轮 | 2440 万 | 572 万 |
| 第 16–33 轮（18 轮） | 4990 万 | 1981 万 |

后 18 轮的花费是前 15 轮的**两倍多**，轮次更少。所以：**跑满 15 轮就换新会话 id**，`browse-session.json` 记着这个段跑到第几轮，DSH 重启也不清零。

换会话时**不搬历史**。搬过来就等于没换。新会话开局只带三样能接上的东西：状态文件、当天的活动记录、轮次账本。

## 踩过的坑

### prompt 里写死时间

唤醒 prompt 开头原来写死「现在是 18:30–08:00 自由时间」。窗口后来改了，prompt 没改，于是下午两点它说自己处在夜间自由时间。

改法：**prompt 里不写时间，让它去读钟。** 同理，所有「昨天/今天/刚刚」都不出现在 prompt 里。

### UTC 和本地时区

「今天发过说说了吗」这条检查用了 UTC 日期。本地凌晨发的记录在那边的日期是前一天，于是每轮都提醒「还没发」——一天能发三遍。

改法：日期一律用本地时区算。所有跨天判断都显式带时区。

### 定时任务失败会静默跳过

到点该跑的任务，脚本崩了但插件不知道，当轮就跳过了，日志里只有一行。

改法：这类「必须发生」的事要有产出物才认定成功（文件在不在、日志有没有新行），而不是「我调用过了」。

### 唤醒 ≠ 在干活

早期唤醒后 agent 回一句「知道了」，然后什么都不做，也算跑完一轮。

改法：prompt 里明确要求「这一轮得有一件具体的事，做完写一行落到文件里」。真的不做，要说明这一轮不做什么、为什么——**不许只回「空着」。**

## interest：只捡被丢掉的

入站消息先过一道门控（白名单、@、静默时段），被丢掉的不会进入任何人视野。

`interest` 只读这批「被丢掉的」，和关键词表比对，命中才唤醒。所以它**不会**把已经在正常处理的对话再叫一遍。

- 只唤醒**这个群自己的会话**，绝不把群内容塞进私聊（不同群是不同房间）。
- 上限：两次唤醒至少隔 20 分钟、一小时最多 3 次、夜间静默。
- 关键词粗：会漏（没命中就不叫），也会误（误了就加进 mute 表）。这是取舍，不是 bug。

## 配置

```yaml
- id: ming-browse
  config:
    workspacePath: 'D:/my-workspace'
    agentPreset: ''                 # 空 = 用全局默认
    gapMinutes: 30                  # 所有会话都闲多久才醒
    freeWindows:
      - { start: '18:30', end: '08:00' }
      - { start: '13:50', end: '18:15', only: 'rest' }   # 只在非工作日
    perDay: 8
    minGapMinutes: 30
    sessionRounds: 15               # 跑满这么多轮换新会话
    holidaysFile: 'live/holidays.json'
```

`holidays.json` 只有两个键：`off`（额外休息日）和 `work`（调休上班日）。表里没有的按周末算。

## 自测

```bash
node browse/qa-rotate.mjs
```

假 ctx、不花钱、十秒跑完。断言：前 15 轮不换会话、第 16 轮换、换完那一轮的 prompt 带提示、新会话从 1 起算。
